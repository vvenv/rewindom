# 用户与权限

本篇介绍租户内部的用户管理与 RBAC 权限体系。这里的「用户」指租户管理员（工作台使用者），不是站点会员。

## 用户管理

在管理后台 → 用户页面：

- 创建用户（邮箱 + 初始密码）
- 编辑用户信息
- 启用/停用用户
- 重置密码
- 分配角色

用户登录后进入工作台（`/app/*`），按角色权限访问各功能模块。

## RBAC 权限体系

权限基于角色（Role-Based Access Control）：

- **权限（Permission）** — 细粒度操作许可，如 `site.write`、`user.manage`
- **角色（Role）** — 一组权限的集合，如「管理员」「编辑者」
- **用户** — 通过分配角色获得权限

### 权限命名

权限按 `<模块>.<动作>` 命名：

| 权限          | 含义                 |
| ------------- | -------------------- |
| `site.read`   | 查看站点             |
| `site.write`  | 编辑站点             |
| `user.manage` | 管理用户             |
| `role.manage` | 管理角色             |
| `audit.read`  | 查看审计日志         |

### 角色管理

在管理后台 → 角色页面：

- 查看权限目录（所有可用权限）
- 创建角色并勾选权限
- 编辑角色权限
- 删除角色（已分配的角色需先解绑）

### 默认角色

新租户通常有预设角色：

- **管理员** — 拥有全部权限
- **编辑者** — 站点内容编辑权限，无用户管理

可按需自定义角色。

## 权限检查

### 前端

```tsx
const { hasPermission } = usePermissions();
if (hasPermission("site.write")) {
  // 显示编辑按钮
}
```

无权限的 UI 元素直接不渲染，不只是禁用。

### 后端

```typescript
// 路由级中间件强制校验
app.get("/api/site/docs", requirePermission("site.read"), handler);
```

后端校验是最后一道防线——前端隐藏 UI 只是体验优化，不能依赖它做安全。

## 审计日志

所有写操作（创建、更新、删除）都记审计日志：

- 谁（user）
- 在何时（timestamp）
- 对什么资源（module + action）
- 做了什么变更（before/after）

审计日志在管理后台 → 审计日志查看，支持按模块、动作、时间筛选。

## 与会员的区别

|          | 用户（User）      | 会员（Member）      |
| -------- | ----------------- | ------------------- |
| 身份     | 租户管理员        | 站点访客            |
| 入口     | `/app/*`          | `/member/*`         |
| 权限体系 | RBAC 角色权限     | 会员门控（有/无）   |
| 管理     | 管理后台 → 用户   | 站点管理 → 站点会员 |

详见 [会员系统](/docs/members)。
