会员是**站点访客**的账户体系，与工作台里的用户是两套完全独立的身份。

## 会员 vs 用户

|          | 会员（Member）      | 用户（User）      |
| -------- | ------------------- | ----------------- |
| 是谁     | 站点访客、终端客户  | 站点的运营者      |
| 入口     | `/member/*`         | `/app/*`          |
| 登录页   | `/member/login`     | `/login`          |
| 能做什么 | 看会员专属内容      | 管理站点与数据    |
| 在哪管   | 站点管理 → 站点会员 | 管理后台 → 用户   |

两套身份的会话互不影响：一个人可以同时是某站的会员和另一套系统的管理员。

## 开通

会员是按租户开通的能力，**默认关闭**。没开通时页头不会出现登录 / 账户入口——挂一个
点进去 403 的按钮比没有按钮更糟。

开通后页头自动多出会员入口，具体展示形态在页头设置里调。

## 登录方式

会员通过 `/member/login` 登录，凭据方式由租户配置：邮箱密码，或 OAuth（GitHub、
Google、Microsoft 等）。

OAuth 需要在平台侧配好应用凭据。工作台与站点会员**共用同一条 IdP 回调地址**，回调时
按 state 分流到对应的身份体系——两套身份不需要各注册一个 OAuth 应用。

## 会员专属内容

在页面的可见性设置里选「需要会员」：

- 未登录访客拿到的是**不含正文**的页面骨架，正文根本没发出去
- 登录会员由前端补齐正文
- 搜索引擎只能索引到公开部分

关键点是「服务端不发」而不是「前端藏起来」——CSS 隐藏的付费内容在浏览器里点两下就
看得到。

## 会员管理

站点管理 → 站点会员：查看名单、启用 / 停用、查看活动记录。

会员登录后可以在 `/member/account` 自助管理个人信息与密码。

## 什么时候需要会员

适合有内容门控需求的站点：知识库、课程、仅会员可下载的资源、留资后解锁的内容。

纯展示型站点（落地页、官网）不需要——保持关闭即可。
