# 多语言（i18n）

首期支持 **`zh-CN`（默认）+ `en`**，语言列表集中在 `@rewindom/shared` 的 `APP_LOCALES`，可扩展。

## 两套多语言（不要混）

| | **代码多语言** | **数据多语言** |
| --- | --- | --- |
| 是什么 | 产品自己的 UI / API 错误 / 审计模板 | 租户内容：商品名、详情、option 名与值、CMS 文案、套餐名 |
| 存哪 | `client/locales/{zh-CN,en}.json`、`server/i18n.ts` | 数据库。商店商品是扁平 locale map：`{ "zh-CN": "杯", "en": "Mug" }`；官网 CMS / 会员套餐是 `{ __i18n: { … } }` |
| 跟谁走 | 操作者的界面语言（i18next / `Accept-Language`） | 站点访客语言；编辑时用**内容语言**切换器填写各语种 |
| 语言列表 | `APP_LOCALES` | 同一份 `APP_LOCALES`（可填的语种），但**不是**给字段再复制一套 `fieldTitleEn` |

禁止：

- 为某一种内容语言在模块 locale JSON 里加平行字段（如 `fieldTitle` + `fieldTitleEn`）
- 把商品文案写进 `client/locales/*.json`
- 用工作台 UI 语言去当商品缺省文案的唯一来源（店面按站点 locale 解析数据 map）

编辑 UI：同一套控件（名称、详情、选项名），上面一个内容语言 Tab；slug / SKU / 价格 / 库存等标识与数字字段不随语言变。

## 优先级（UI 语言）

与主题 / 布局同构：

1. 用户本地选择（`localStorage: app-locale`）
2. 租户默认（`TenantSetting[appearance].locale`）
3. 平台默认（`AppSetting[platform_settings].default_locale`）
4. 代码兜底 `zh-CN`

## 前端 UI

| 位置 | namespace | 说明 |
| --- | --- | --- |
| `packages/client-kit/src/i18n/{common,shell}/locales/{zh-CN,en}.json` | `common`、`shell` | 壳层 |
| `packages/builtin/<id>/client/locales/{zh-CN,en}.json`（外部模块 `modules/<id>/...`） | 通常 = module id | 模块 UI |
| `client/i18n.ts` → `client.i18n` | — | 组装层 `registerI18nBundles` |

导航 label 用 `namespace:key`，渲染时 `translateAppNavSections`。

## 后端 API 消息（按 code）

**不要**与 client 共用 JSON。契约是稳定 **code**，不是中文句子。

| 位置 | 说明 |
| --- | --- |
| `server-kernel/.../i18n/catalogs/kernel-{zh-CN,en}.ts` | 通用 / 认证等 |
| `modules/<id>/server/i18n.ts` → `server.i18n` | 模块 API + 审计模板 |

推荐抛错 / 回写：

```ts
throw new NotFoundError("notes.not_found");
// 或
throw new AppError({ code: "notes.not_found", status: 404, params: { id } });
sendCodedError(reply, 400, "auth.credentials_required");
```

边缘 `onSend` / error-handler 按 `Accept-Language` + `code`（及 `params`）翻译 `{ error, code?, params? }`。  
插值语法：`{{name}}`。**禁止**再以中文句子作为 API 错误契约。

租户侧 / 公开面文案遵循 **租户无感知**（`docs/design/tenant-config.md` §5.8）：UI、API `error` 兜底句、审计模板勿写「租户」「Tenant」；稳定 `code` 与内部标识不受限。

`ModuleLoader.registerAll` 会先 `registerI18n()` 合并各模块 `server.i18n`。

## 审计 details：模板 key + JSON

**是最佳实践**：入库保存结构化数据，展示时再按查看者语言渲染。

| 列 | 用途 |
| --- | --- |
| `detail_key` | 稳定模板 code，如 `notes.audit.created` |
| `detail_params` | JSON 参数 |
| `details` | 遗留纯文本，或写入时渲染的 **zh-CN 检索副本** |

写入：

```ts
await emitAuditLogFromRequestSafe(events, log, request, {
  action: AuditAction.NOTE_CREATE,
  resource: note.id,
  detail_key: "notes.audit.created",
  detail_params: { title: note.title },
});
```

展示（client）：`translateAuditDetail`——`notes.audit.created` → `t('audit.created', { ns: 'notes', title })`；认证等内核模板放在 `audit:detailTemplates.*`。

旧行仅有 `details` 时原样展示。新写入一律用 `detail_key` + `detail_params`（`details` 由服务端按 zh-CN 模板自动填检索副本）。

## 官网 URL

无前缀 = zh-CN 主入口；`/{locale}/...` = 带 locale 的静态页。见 marketing 模块。

## 官网 CMS：库存文案 vs 复制页面

段设置里的可本地化默认值、页面预设的 `text` / `titleKey` / `descriptionKey`，必须是
`ns:key`（与 `client/locales` 同一条）。创建时展开成整张 `{ __i18n }` 表，不要先
`t()` 成单语字符串。

复制到另一语言（`relocalizeSections`）：

| 字段状态 | 写入目标语言 |
| --- | --- |
| 仍等于 catalog 库存句 | 目标语言的库存译文 |
| 租户改过 | 源语言原文（当翻译起点） |

1:1 的模板段把同一条 key 写在 setting `default` 上（`headingSettings({ headingDefault })`）。
同一段被多张预设共用（如商品列表的 heading）时不要硬塞一个 default，复制路径会按
catalog 反查。

CMS 文案 / 链接 / **页面标题与描述**的渲染期占位符是 `{token}`（页脚 `© {year} {site}`、events 的 `{topic}` / `{event}` / `{feed}`），
与代码 i18n 的 `{{param}}` 不是同一套。实现见 `packages/builtin/marketing/shared/site-interpolation.ts`。
未识别的 `{foo}` 原样留下；链接里空掉的路径段会收掉。不要在渲染器里暗改租户填的 href。
带 `:slug` 的模板把这些 token 写进预设标题 / 描述，公开面 `<title>` / meta 用页面设置再插值。

## 扩展语言

1. `APP_LOCALES` 追加
2. 补 client-kit `{common,shell}/locales/<locale>.json` + 各模块 `client/locales/<locale>.json`
3. 补 kernel / 各模块 server catalog 的对应 locale
